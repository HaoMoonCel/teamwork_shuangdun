## 5. 共享边界规矩（冲突规避）

1. **`symbols.js` 是唯一高风险文件**：牛的资源库、你的 `aiResults.js` 模拟数据都引用它。结构变更（字段改名、删字段）前必须在群里说明，大家确认后牛再改。
2. **改动全局文件前先打招呼**：router、App.vue、NavBar、base.css 谁碰都要先说。
3. **提交前一律 `git pull --rebase`**，再 commit 再 push。
4. **杨只通过接口约定与前端对接**：不直接改前端代码；曾只在接入阶段按约定替换数据源。
5. **接口约定是全局关键路径**：杨的 `api-contract.md` 未出之前，曾按约定草案/经验先行 mock，不要干等。

## 6. 协作流程

- **分支**：暂不建分支，4 人直推 `main`。守住围栏 + 规矩，冲突概率很小。
- **提交信息格式**：`feat: 描述` / `fix: 描述` / `docs: 描述` / `test: 描述`
- **沟通**：群里改动前同步；问题用 Issues；文档放 `docs/`。
- **每天收工**：`git pull --rebase` → 提交 → push，避免堆积冲突。
